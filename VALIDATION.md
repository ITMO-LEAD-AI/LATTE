# Validation and compatibility

Version 1.2.0 restores the DETR recipe from DETR_LATTE_Repo(1).py.

Checks performed:

- Every Python file parsed successfully.
- RT-DETR attention, calibration, pipeline, utilities and evaluator match the
  earlier RT-DETR-only ZIP byte for byte.
- The DETR attention class matches the original class's complete Python AST,
  including parameter names, tensor operations and direct output reshape.
- DETR does not import the RT-DETR evaluation routine.

Not performed here: GPU execution, unit tests requiring PyTorch, model downloads,
or COCO calibration/evaluation. PyTorch, Transformers, pytest and COCO are absent
from the delivery runtime. Matching numerical results are not yet verified.

Intentional packaging changes to the original DETR script:

- Paths and calibration sizes/epochs/batches are configured through YAML.
- Activation tensors are collected dynamically instead of preallocated, retaining
  the original bfloat16 storage and decoder-hidden-state/o_proj pairing.
- Chunk loops handle partial chunks and debug runs.
- Unused layer-normalization hooks and commented experiments are removed.
- New checkpoints use explicit layer records; original transforms/cos_loss/mse_loss
  checkpoints are also accepted.
- Temporary prediction JSON is deleted; only summary results persist.
- Full-dataset COCO evaluation follows the original; explicit subsets restrict
  evaluated image IDs.

The original script uses RT-DETR preprocessing during DETR calibration and DETR
preprocessing during evaluation. This is intentionally retained, not corrected.
The strict original id2label lookup is retained, not replaced by silent filtering.
The cause of the previously reported KeyError: 91 has not been reproduced here.
Restoring source semantics is not proof that the runtime error is resolved.

Recommended first check: evaluate the original working DETR_LATTE_Repo.pth by
setting checkpoint in configs/detr_evaluation.yaml to that file. First set
layer_counts to [0] and confirm baseline metrics, then restore [0,1,2,3,4,5,6].
Use the same COCO split, local model files and environment as the original run.
Do not use DETR checkpoints generated by the earlier refactored implementation.
